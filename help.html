FLEX guide

FLEX shows everything about a piece of ground at once: the globe and terrain, map layers, LiDAR point clouds, surface points and tracks, and 3D cave surveys. Work is kept in projects (one per area), and any area can be baked into an offline viewer that runs on a phone underground.

Setting up

FLEX is a small program (a Node server) that you run on your own computer, opened in a web browser. Your data stays on your computer.

  1. Install Node.js Version 18 or newer, from nodejs.org (the LTS installer is fine).
  2. Get FLEX and its parts Download or clone FLEX from GitHub (github.com/fe-roz/FLEX), open a terminal in its folder, and run: 
    npm install
  3. Add your map keys Copy Tokens.js.example to Tokens.js and paste in a Cesium ion access token (a free account at ion.cesium.com → Access Tokens). That token gives the 3D terrain and Bing imagery. A Google Maps key is optional, for Google's photorealistic 3D tiles. Tokens.js stays on your computer: it is never committed or shared.
  4. Start it 
    node server.js
    then open http://localhost:8081/index.html in Chrome or Edge. On Windows you can make a FLEX.bat that does both (it is ignored by git, since it holds your own paths).
  5. Optional: CalTopo, LiDAR, exports Each is set up when you first need it: a CalTopo key for private maps, a local Entwine server for your own point clouds, and a Python environment for offline viewers.
Updating: Updates in the top bar shows when a newer version of FLEX is available and fetches it (FLEX must be a git checkout). Restart the server after an update.
Keep FLEX's folder private bits private. user_files/ (your projects, My data, keys), Tokens.js and FLEX.bat are never part of FLEX on GitHub. Survey data and cave locations are sensitive: share them with sync files, on purpose, with the people you choose.

Your first area

  1. Make a project Project → ＋ New project. Give it the area's name. Your name (asked once) is written on every change, so friends can see who did what.
  2. Bring in a cave Caves → + Import PLT / Breakout / Walls (a Compass .dat works too: its readings are reduced to positions from its first station, with the file's own declination already applied, so leave the declination box empty). Then place it: select a station, Anchor a station to the globe at the entrance, and check the magnetic declination. More stations pinned as control points warp the survey to fit.
  3. Add the surface Surface: draw points, lines and areas, import KML / GPX / GeoJSON, or link a CalTopo map so the group's markers and tracks appear.
  4. Add layers Layers for imagery and hillshade — and Your map layers for your own: a GeoTIFF or a tile link (see below). LiDAR for point clouds.
  5. Save Save puts the changes into the project (the count shows how many are waiting). See Saving.

Switches and tick boxes

  • Switch — on (green) or off . It takes effect at once: Leads, Area names, Show LiDAR Datasets, the Ground and height filters, Show features and Labels in Surface. Click it or its words; with the keyboard, Tab to it and press Space or Enter.
  • Tick box — only in lists where you pick several things and then press a button, like Caves → Recent PLT (tick some, then Load), and in forms saved with their own button.
  • Row switch (the small switch at the start of a row in Caves, Surface, the point clouds and Terrain lists): on = shown · green ring = loaded but hidden · grey ring = not loaded yet. Switching a not-loaded row on loads it and shows it. Folders and features inside a file are always loaded, so they are on or green-ringed.

Minimap

M shows or hides the minimap. It turns with the camera, so up is the way you look; the small compass shows where north is. The yellow shape is the ground the camera sees: a wedge from your position when you look ahead, a box when you look down. Outlines show where detail is drawn: blue for terrain patches, purple dashed for point clouds. Hover over the minimap for the legend, and over an outline for its name.

Projects and My data

A project is everything about one piece of ground, kept in one folder: its caves and where they are placed, surface points and tracks, documents, leads and notes, the CalTopo map and point clouds it uses, and the history of every change. One project is open at a time. Friends get a project by sync file.

👤 My data is your own collection, outside any project: anything you load or draw with no project to put it in lands there, and stays across sessions. It is never synced. Built-in maps belong to neither.

Same trip

There is no Trips panel. A trip is only a way to see which surveys and documents belong together. FLEX suggests one from the survey dates: surveys of the project on the same day or on consecutive days, with the documents dated inside those days. A survey's details (Related) and its card then say Same trip (12–13 Oct): surveys B, C · 3 documents, each one clickable; it shows only when there is something to show. In Docs, tick Group by trip to put the documents of one trip together (off unless you switch it on; remembered on this computer).

To correct a suggestion, press Trip… on the survey's card, or in a document's ⋯ menu: pick another trip, start a new one (name optional; a date or a range; people optional), or choose Not part of a trip. It is saved at once like a point, listed in History, and carried by sync files; a trip you set yourself wins over the suggestion.

The project pane

Project, with a project open, is the project at a glance. At the top: its name (✏️ to rename, Switch… for another project), its description and its folder (⧉ copies the path). When changes wait for Save, a yellow Unsaved changes box lists them, with Save and Discard.

The numbers are buttons: caves, length, stations and depth open Caves; open leads open Leads; documents, photos and videos open Docs on that tab; points open Surface; people and last change jump to History below.

Connected shows what the project brings in. Its CalTopo map comes with Open in CalTopo ↗, and with how many of the project's surface features CalTopo doesn't have yet (the same name within 15 m counts as there); ⇩ Download them gives those as a KML to Import… in CalTopo. Its terrain, hillshade and point clouds each have a switch and → to their panel. Folder lists what waits in the project's To sort folder. Below: Field survey, Sync files and History (the last 5 changes; All history… for the rest, with undo).

Adding things to the project happens where they are: ← in Caves and Surface, on a point cloud in LiDAR. A cave's ⋯ in Caves has Copy CalTopo tag, Caves in this file… (link it to a cave, or split it into the caves FLEX finds) and Remove from project.

Systems, several caves in one file, several entrances

A system groups caves that connect or belong together (ridge or valley systems); their survey files stay separate. In Caves, under the project's files, Systems lists them with the caves inside and the totals (length added up, depth from the highest to the lowest point). ＋ New makes one; ⋯ on a system renames it, changes its caves or deletes it. A cave's ⋯ → Cave “…”… → Systems… (also on the cave's card) puts it in or takes it out. The cave's card and the details panel show its system.

A multi-cave survey file is one file placed once that holds several caves (a valley's survey in one PLT). The file's ⋯ → Mark as multi-cave file… (or Caves in this file…) lists its surveys: give each to a cave, leave it under Surface / not yet sorted, or mark it a surface traverse (it then belongs to no cave and is drawn as surface). Start from the caves FLEX finds fills the list with surveys joined underground. Each cave behaves like any other: its own notes, leads, sketches, labels, system and export; under the file's row Caves lists them, and the unsorted surveys stay visible there until you sort them. Under the file each cave has its own ⋯: Export survey… writes only that cave's surveys, Split into its own file… writes a new survey file holding just that cave (placed the same, so nothing moves; the big file is never changed; History undoes it), and Move to another project… splits it first, then moves it. The file's own row still exports the whole file. Not a multi-cave file in the same dialog switches the mark off (the caves stay).

A cave can have several entrances: more markers with the same id in their tag. Caves → Cave entrances on the map numbers them (“entrance 2 of 3”); the main one places the file, Pin the cave here holds another entrance's station at its marker (a pin), and Fit the whole file to its entrances does both for every marker of the file—for a multi-cave file that includes the entrances of its other caves, so the whole file fits. An entrance whose cave has no survey yet is just a surface point.

Archive, move, snapshot, footprint

The project pane's Manage block holds the rest of a project's life. Archive hides a project from the list and makes it read-only; it still opens (a banner says so, with Unarchive), a switch under the list shows archived ones, and other devices see it after the next sync file. Nothing is deleted. Open a snapshot shows the project as it was at the end of a day you pick; the banner reads “Snapshot of <date> — read-only” and nothing can be changed until Leave the snapshot.

A cave's ⋯ in Caves has Move to another project…: the cave goes with its survey files, notes, leads, segments, area labels, sketches and documents. It waits for 💾 Save like other moves; files are copied, never deleted, and both projects keep a record (“moved to …” and “moved in from …”) in the pane and in History. Footprint: Draw… lets you click the corners of your own outline on the map (Enter or Done to finish, Backspace to take one back, Esc to cancel); Edit drags corners, a click on the outline adds one, a right-click on a corner removes it; Clear goes back to the computed one. Move to My data… (Surface features) takes folders of points, lines and areas out of the project into My data on Save. With no project open, From a cave set… turns a cave set from My data into a new project.

Leads at stations

Add one: right-click a station (or the shot next to it) in a cave on the map and choose Add lead at A1…; or click the station and press Lead on its card. The same form opens everywhere: description, size, status, what it needs, priority, air, who found it and when. With a project open, and the cave one of its caves, the lead is a record of the project (it syncs, has a history, and Review and the CSV include it). With no project, or for a cave the project does not have, it is kept in My data on this computer. Click a lead's “?” to see it in the details panel; Edit there changes it, closes it (set the status to dead end, surveyed into, mop-up done or not a lead) or removes it.

Where they show: every open lead is a “?” at its station's own place and height in the cave, with a short label, whether it comes from the project, My data or the survey file (Breakout, Walls). The Leads switch in Caves hides them all; Closed leads draws the closed ones faded. They are listed in Leads. A lead from a survey file becomes a record the first time you save it, and then shows once.

Documents in an export: in the Export panel, Include documents (on by default, with the count and size) carries the open project's scanned notes, photos and sketches that belong to the exported caves, and the ones about the project as a whole. Page images only (PDFs and videos stay in the project). They open in the portable viewer (📚 Documents, and from a station's card) and in FLEX Field, tagged to their stations and caves. The single-file viewer.html carries the pages itself up to 12 MB; more pages come as docs_<fingerprint>.jpg files beside it (keep the zip's files together). If the same project is also synced on the phone, each document shows once. In the viewer, adding a note is always at hand; every other change (leads, tags, turning or removing pages) waits behind a small Edit button on the card, per item. The viewer remembers its display choices per map; a new map starts with ghost walls coloured by elevation.

In an export: the exported map carries the open leads of its caves (the project's, My data's and the file's, each once; closed or removed ones stay out) with station, position, description, size, date and status. The portable viewer and FLEX Field show them as the same “?” and list them under Leads. Older exports open as before.

Selecting in 3D

Each click on the same cave goes one level deeper; the details panel shows where you are.

🕳 Ridge Cave›Survey A›Segment 3›Station A12
  • A click inside the selection goes one level deeper. Segments are skipped where there are none or they are turned off.
  • A click elsewhere selects the same level there: with a survey selected, the next click selects another survey.
  • Clicking the selected station again goes back to the cave. Empty space or Esc clears it.
  • Right-click a cave for a Select menu with every level, to jump straight to one.
  • Double-click a cave's name in Caves to fly there.

Points, lines and areas: info first, editing second

  • A click shows brief info in the details panel on the right: what it is, where it comes from (the project, 👤 My data, the CalTopo map or a data file), a few lines of its description, and how many photos, videos, documents, notes and leads go with it. A click never edits: use Edit for that.
  • Badges next to the source: waiting for CalTopo (saved here, sent when FLEX is online again), changed in CalTopo, changed in CalTopo: choose (edited in both places: click it to see both versions and keep one), not in CalTopo (a project feature the project's CalTopo map doesn't have), read-only.
  • More: rest the pointer on the details panel for a moment (or press ⤢ More) to open a larger panel beside it with everything:
    • the folder it is in (click a folder to open it in its list) and Open in CalTopo ↗ for a CalTopo feature;
    • its position as latitude, longitude and UTM; the terrain height there, the LiDAR ground where a loaded point cloud covers it, its own height and how far that is above the ground;
    • its colour, symbol, whether its name shows on the map, when it was made and changed, and by whom;
    • what is related: for a station its survey, segment, the stations it connects to, its shots (length, azimuth, inclination) and LRUDs; for a survey its stations, length, segments, dates and team; for a cave its surveys, entrances, length, depth and open leads; for a point the cave it marks the entrance of and its project;
    • what is nearby: up to three of the nearest stations, cave entrances, leads, other points (from the project, My data, CalTopo and data files) and trails or lines, each with distance and direction, like “120 m SE (128°)”. For a line, the distance is to the line itself, not to its corner points. For a lead or a station it also says how far below the ground it is (the LiDAR ground where a loaded cloud covers it, the terrain otherwise);
    • for a line or track, a Route section: a graph of the height along it (terrain, and the LiDAR ground as a second line where a cloud covers it; hover to see distance and height, and a dot follows on the map; the steepest stretch is red), climb, descent, the steepest grade and where, the recorded time if the track has times, and the walking time worked out two ways, Tobler (a hiking function: about 5 km/h on the flat, slower up and down) and Naismith (5 km/h plus 10 minutes for every 100 m climbed). Both are for one person on foot and do not know about brush, rock or water. Points within 10, 25 or 50 m (your choice is kept) of the line are marked on the graph and listed as “On the way: Gate · Spring”; click one to open it. Start and End say what is within 30 m of each end (an entrance, a point, another line);
    • the whole description, notes, leads, photos, videos and documents.
    It goes away when the pointer leaves, unless you drag it by its header, pin it with 📌 or click inside it. × or Esc closes it.
  • Show in list opens the list that holds it ( Surface or Caves) and shows its row. While that list is open, a click on the map opens the row's folder, scrolls to it and makes it flash.
  • Edit opens one editor, the same for every point, line and area: name and description, folder, colour, CalTopo symbol, name on the map, and for a point its position (type latitude and longitude, or UTM zone, easting and northing). Move on the map lets you drag the point (or click where it goes; Esc cancels). Delete asks first.
  • Edits go where the item comes from: the project (undo in History), 👤 My data, or the CalTopo map itself. A change to a CalTopo item is held in FLEX (marked edited, moved or deleted, and drawn that way on the map) until you press Send to CalTopo; nothing reaches CalTopo by itself. If the CalTopo key on this computer can only read, FLEX tells you how to enter one that can write. Features from a data file are read-only: FLEX shows the file as it is.
  • Photos and videos are listed apart from other documents ( Docs → 🖼 Photos and 🎞 Videos). A video plays in the larger panel or in the document viewer and stops as soon as you close it. If your browser can't play one (often HEVC from phones), ⇩ Original saves it for your own player.
  • Documents can be tagged to a surface point, line or area too (🏷 Tags → find it by name).

The project folder

Each project is a folder, by default in user_files/projects/<name>/; it can be anywhere, a shared drive folder included. Put scans, reports and maps in it however you like; Docs shows it as it is on disk. FLEX keeps its own information in a hidden .flex folder inside it.

Caves

  • Import: Caves → + Import PLT / Breakout / Walls (Compass .plt, Breakout exports, Walls shapefile exports).
  • Place: select a station → Anchor a station to the globe. Add control points (more stations pinned to known spots) to rubber-sheet the survey into place. Check the magnetic declination; the wizard can look it up from the World Magnetic Model.
  • Style: each cave's ⋯ menu, or 🎨 All caves at the top of the panel for every cave at once: dots, names, colour, walls (blocky / smooth), opacity, area names.
  • Area labels (🏷 Labels in a cave's details): names for parts of a cave, such as “Big Room”. Fly the camera to the spot, type the name and press Add at camera; rename, move (⤓ to the camera) or delete them in the same list. A cave in the open project keeps its area labels in the project: changes go straight in (undo in History), and they travel with it to other computers and in sync files. A cave in 👤 My data keeps them in My data. Moving a cave between the two (← / →) takes its labels along; labels a project cave had from before move into the project by themselves, once. Exported maps show them.
  • Colour by survey, elevation, depth below ground, or difficulty.
  • Replace survey file keeps the placement when a cave's survey is updated, and warns about stations that changed.

Export survey… (a cave's ⋯ menu) writes the survey as Survex (.svx), CSV (one row per shot: survey, from, to, length, azimuth, inclination, left, right, up, down) and Compass plot (.plt) files; tick the ones you want. For a cave in the open project they go into the project folder, Caves/<cave>/Survey/, replacing the last export, and FLEX says where; otherwise they are downloaded. Everything is in metres and degrees. FLEX keeps station positions rather than the readings taken in the cave, so the shots are worked out from the positions; the Survex file fixes the anchored station at its latitude and longitude with the cave's declination, and each file's first lines say what it can't carry.

Sketches and files

A sketch is a scan (a jpg, png, webp or tiff picture, or a PDF) of a cave sketch, attached to a cave, a survey or a station. Sketches belong to a project; with no project open FLEX says so and offers New project….

  • Add one: a cave's ⋯ menu → Add sketch…; or select a cave, survey or station in 3D, open its Files tab and press Add sketch…, or drop the scan on the Files tab.
  • Where it is kept: the scan is a document of the project, linked to what you attached it to, with the original file unchanged. In a project folder the original is filed by the folder rules: a cave's sketches in Caves/<cave>/<cave> - general/, a survey's (and its stations') in the survey's own folder, Caves/<cave>/<cave> - <code> <survey name>/. A project without a folder keeps the original inside the project.
  • The Files tab of a cave, survey or station lists its sketches, documents, photos and videos, and for a cave the files FLEX generated (the survey export). What belongs to the surveys and stations below is folded under more further down. Click a file to open it in the viewer.
  • On each file: rotate a quarter turn, and ⋯ for Rename…, Links… (move it to another cave, survey or station, or add more), plan or profile sketch, and Remove…. Removing asks first, can be undone from History, and never deletes the file in the project folder.

Surface features

Surface lists the project's things on the left (its CalTopo map with the project's folders and items merged into its tree, data files) and 👤 My data on the right. ▸ opens a row in place: a folder shows its folders and features (click one to highlight it, double-click to fly there, ✏️ to edit); the CalTopo map and data files show their own folders, each with its box.

The menu on every row. On a point, line or area: Info, Edit, Rename, Colour, Label on/off, Move to folder, Fly to and Delete. It edits the same way as the info panel, and the change goes where the item lives: the project, My data or the CalTopo map. On a folder: Display… (names, colour, line width, symbol and opacity for everything inside), Names on/off, Rename, New subfolder, Move and Delete. Delete asks what happens to what is inside: it moves up one level, or it is deleted too. Data files are read-only, so their items only have Info and Fly to, and their folders only Display…. The same goes for CalTopo's Markers, Lines and Polygons groups. Entries that can't be used are greyed out; hover over one to see why.

  • Show features (the switch at the top) hides or shows everything on the surface at once — project features, CalTopo, data files and your points — without changing what each one is set to. The 📍 icon is struck through while it's hidden.
  • Labels (next to it) turns all names on the map on or off: project points, CalTopo and data-file features, and your own points.
  • Surface → ＋ Point / Line / Area to draw, or import KML / KMZ / GPX / GeoJSON. Points can carry lead details (status, needs, priority).
  • Folders work like CalTopo's; ⇩ downloads a folder as KML / GPX / GeoJSON to upload to CalTopo.
  • Cave entrances marked on points (flex: cave=…; station=…) are listed in Caves → Cave entrances on the map, with Place the cave here.
  • With the project's CalTopo map loaded, ⧉ Duplicates of CalTopo lists the project's features that CalTopo already has (same kind and name, within 15 m), ticked; Remove ticked from the project drops them, so CalTopo's copy is the one shown. Undo in Project → History.
  • Very long GPS tracks are drawn simplified (to about 2 m), so they don't slow the map; the full track is kept.
  • Display of a folder: the button on a folder's row (project folders, a My data sitting, the CalTopo map and its folders, a data file and its folders) sets names on or off, one colour, the line width, a symbol for points and how see-through, for everything inside. A folder inside another wins over it. Only how FLEX draws them changes: a project folder's colour is the folder's colour in the project (everyone on the project sees it); the rest is kept on this computer. Nothing is written to CalTopo, and data files stay as they are. Reset puts each item back as it was. The button turns green while a folder has settings.
  • CalTopo features in no folder are listed under Markers, Lines and Polygons, as CalTopo lists them (only in FLEX).
  • Click a row to select the item: its full info opens and it is marked on the map and in the list; Esc, a click on empty map, selecting something else or closing the Surface pane removes the marks. Double-click flies there.
  • Every item has its own row switch: project points, lines and areas, the items of the CalTopo map (and its Markers / Lines / Polygons groups) and of data files, and the points, lines and areas in My data. Off hides the item and its name on the map; the choice is remembered on this computer.
  • The CalTopo map is listed by its name (from your key's map list, else the map's own title, else its id). The name is kept in the project. Its menu has Rename… (only FLEX shows the new name; CalTopo is not changed), Move to My data and Remove from project (both wait for 💾 Save, which unloads the map for Remove; nothing is deleted in CalTopo, and History undoes it). A map in My data has Remove.
  • As soon as one project item is not in CalTopo, a note says so with Send… and Highlight (held changes and new folders add Review…): Highlight rings every such item on the map and marks its row in the list (folders open); click Clear highlight to remove it. The note goes by itself when nothing is left to send.
  • With a CalTopo map loaded, project points, lines and areas the map doesn't have (same kind and name, within 15 m) are marked not in CalTopo (to send in the merged tree under the project's map); a folder says how many it holds.
  • Show in list in the details panel opens Surface (or Caves) at the item: its folders open, the row scrolls into view and flashes.

Heights

Every point on the map has one height, and which one depends on where it comes from. Cave data (stations, shots, lines and their names) always keeps its surveyed height. A cave entrance in CalTopo whose description has z= in its flex: line is drawn at that surveyed height. Other CalTopo points stand on the ground. Your own points (in a project, not sent to CalTopo yet, or in My data) keep their own height: when you make or move one, FLEX measures the ground from the finest terrain it has there and keeps that number with the point, together with where it came from (terrain, survey, GPS or file). Once a project point is sent to CalTopo it follows the ground like the others. Points made before this was kept are measured once and saved. Imported files: KML, GPX and GeoJSON points are put on the ground once at import, and the height the file had is kept and shown as File height in the details. A KMZ placemark that has an altitude and an absolute altitude mode keeps the file's height; without an altitude, or set to clamp or relative to ground, it is put on the ground. Lines and areas are always draped over the terrain. When you add finer terrain than a height was measured from, a small notice says Update heights from the new terrain (N points): Update measures them again; Not now leaves them. Surveyed, GPS and file heights are never changed.

Your own map layers

Layers → Your map layers:

  • ＋ GeoTIFF… — a hillshade, an orthophoto or a georeferenced scan, in lon/lat (EPSG:4326), UTM (WGS84 or NAD83) or Web Mercator. A DEM (one band of heights) is turned into a hillshade. FLEX keeps one picture of it (at most 4096 pixels a side) with where it goes. Other projections: save the file as lon/lat or UTM first (e.g. QGIS → Export → Save As, or gdalwarp -t_srs EPSG:4326).
  • ＋ Tile link… — any map served as tiles, with {z}, {x} and {y} in the link. A key in the link travels with the layer, so don't add private keys to a shared project.

With a project open, a new layer goes into the project (📁) and travels with it; with none, into 👤 My data. They're listed in the one Layers list (📁 or 👤 in front), added from its ＋ Add layer menu; the switch and the slider (how see-through) are yours alone.

The CalTopo map's custom layers. When the loaded CalTopo map is private (read through a key) and has custom layers (CalTopo's Add → Custom Source: Tile, TMS or WMS), they appear in the same Layers list with a in front. FLEX only reads them: add, change or remove them in CalTopo, and FLEX follows at its next read; they go when the map is cleared. At first a transparent overlay is shown and a base layer is hidden (it would cover everything below it); after that the switch and the slider are yours, kept on this computer. WFS sources (map features) and WMS in other projections than Web Mercator or lon/lat are not shown. The tiles come straight from the link: a key in the link works, but a source that needs a CalTopo sign-in, or a server that doesn't allow other sites, gives no tiles. FLEX then says so once and marks the row no tiles.

Terrain

Terrain has its own button in the strip (it works with no project). The panel lists the terrain patches you have — 📁 the project's, 👤 your My data's — each with its hillshade, a switch, ⌖ fly there, ✕ remove, and the move buttons below. World terrain is what shows everywhere else. A patch replaces the world terrain inside its area (and blends into it over 60 m at its edge), so entrances, shallow passages and depth below ground use the precise ground.

  • ＋ Add DEM GeoTIFF… bakes a DEM you already have into a patch (lon/lat, UTM or Web Mercator).
  • ⛰ Generate… makes terrain and a hillshade from the LiDAR, once, with the same code as the FLEX Field export. It needs a point cloud: the project's own point clouds, or (with no project) the ones you have loaded. Choose the area, the LiDAR, the cell size and a name, then Generate; it takes a few minutes and shows in the Jobs strip.

Choosing the area. The picker outlines the area on the map and gives its size in km² (mi² with imperial units). It can be:

  • ✏ Draw… — click the corners on the map; Enter, Done or a double-click on the last corner closes it, Backspace takes back a corner, Esc cancels. A polygon whose edges cross is refused.
  • Project footprint + margin — the project's footprint grown by a margin (200 m to start; change it in the box).
  • A polygon already on the map — a project area, one of your My data areas, a shape of the loaded CalTopo map, or an area in a data file (KML, GeoJSON…), listed by name.
  • The Export panel's box — as before.

Where it is kept. With a project open, in the project: the terrain in its library (it travels in sync files), the hillshade as map tiles in the project folder (FLEX maps/<name>/, which doesn't travel; on another computer that got the project by a sync file the hillshade is redrawn from the terrain, a plain shading of the DEM, light from the north-west). With no project, in 👤 My data (its folder, user_files/mine/: the patch in its stored files, the tiles in FLEX maps/<name>/), and it comes back whenever FLEX starts. The hillshade is also a map layer in Layers (opacity, order); the patch is not.

Moving terrain. With a project open, a 👤 row has ← (into the project) and a 📁 row has → (to My data) and ⇢ (to another project, which you pick). Like other moves the change waits for Save (the row says where it is going and Save counts it; the same button again cancels). On Save the files are copied to the other side and only then does this side let go; nothing is deleted from the disk, and History can bring the layer back.

A patch is up to 3000 × 3000 posts (about 1.5 km at 0.5 m). A bigger area is cut into several overlapping patches that keep the DEM's resolution (up to 9, about 4.5 km a side at 0.5 m; beyond that the posts are widened to fit). They appear as one row, “<name> (n parts)”. Where a DEM has no data (the empty corners of a rotated DEM, the outside of a polygon) the world terrain shows.

In an offline export (FLEX Field, portable viewer): with Terrain → Map terrain, the project's terrain patches that cover the area are laid over the map terrain at their own resolution (choose a fine cell). With Terrain → LiDAR the LiDAR is used as it is. Under Maps, “Satellite source” and “Hillshade” list your map layers: a GeoTIFF layer is baked in as it is (no internet). A tile link, including the project's hillshade, is downloaded while the export runs, so the computer needs the internet (or the tiles must be on it); if that fails the export takes Bing imagery (hillshade: shaded terrain) and says so in its log. WMS links are not exported.

CalTopo

Paste a CalTopo map link in Surface → CalTopo map: link and key. Public maps work as they are. Private maps need a key, kept only on this computer (never in a project, sync file or git):

  • Team account: Team Admin → Details → add a service account with READ. Enter its credential ID, secret, and the team ID.
  • Personal account: the credential from caltopo.com/api/v1/activate (unofficial; it may stop working if CalTopo changes it).

With an account or team ID, Pick a map… lists your maps. FLEX re-reads the map at the Refresh you choose (Off, which reads by hand; 30 s; 1 min, the default; or 5 min); whatever you pick, FLEX never asks CalTopo more than about once a second, and a map read in the last half minute is not read again, so several windows or a bulk send don't wear out CalTopo's patience. If CalTopo can't be reached or says “too many requests”, FLEX waits longer (1, 2, then 5 minutes) and shows its saved copy meanwhile; only what changed is redrawn, and long tracks are drawn simplified (within about 2 m). A map the open project doesn't have shows in Surface under 👤 My data, with its folders; ← makes it the project's map. To link a cave to its entrance marker, put a line like flex: cave=Ridge Cave; station=E1 in the marker's description. Copy CalTopo tag also adds the entrance's height and the cave's id when it knows them (flex: cave=Ridge Cave; station=E1; z=1500.5; id=ab12); z is used for the cave's height when the terrain has none, id finds the cave if it was renamed. Tags without them keep working.

Editing the CalTopo map

CalTopo is the master of the surface features. With a private map loaded through a key, an edit to a CalTopo feature in FLEX (name, description, colour, symbol, folder, position, delete), a new folder, or an item you add from the project is held in FLEX until you press Send to CalTopo: the row says what is held, the map draws the held state, and nothing is written to CalTopo before you press Send. One button, ⇪ Send N to CalTopo (N counts everything that waits), sends it all; ☰ Review lists what will go, with a Drop button on each held change (the item goes back to CalTopo's version). Held changes are kept on this computer, so they survive a reload and can be made offline.

One tree. With the project's CalTopo map loaded, Surface shows one tree under the map's row: CalTopo's folders and items, with the project's folders and items merged in by folder name (an existing “Pits” is the same folder, whichever side made it). An item CalTopo already has shows once. What only the project has is marked to send, in its place in the tree: a project folder CalTopo doesn't have, and the items in it. There is no separate project folder tree. A project with no CalTopo map keeps its own list of folders and items.

Drag and drop. Drag a point, line, area or folder onto a folder (or onto the map's row for the top level). A project item or folder moves at once; a CalTopo item or folder is moved in FLEX and the move waits for Send (a folder CalTopo doesn't have yet is created first). A point from 👤 My data dropped into the tree moves into the project like ← does (it waits for 💾 Save) and then waits to be sent. New folder… (the map row's menu, or a folder's New subfolder…) makes a folder that is created in CalTopo at Send.

  • The key must be able to write. A read-only key (a Team service account with READ) is refused at the first edit; FLEX then tells you to enter one that can write in Surface → CalTopo map: link and key → Change key… (Team: a service account with WRITE).
  • Offline: FLEX keeps a copy of the map on this computer and shows it when CalTopo can't be reached (the status line says so). Edits made then wait and are sent when CalTopo answers again; FLEX says when they've gone.
  • Changed in CalTopo meanwhile: if someone changed the same feature in CalTopo while your edit waited (or since FLEX last read the map), FLEX shows both versions side by side; Keep mine sends yours, Keep CalTopo's drops yours. Decide later leaves it waiting.
  • Changes others make in CalTopo appear by themselves. FLEX keeps a list of what was added, changed or removed between reads, and a log of every read and every edit sent (user_files/caltopo_log.jsonl).
  • What changed since you last looked: an orange dot on Surface in the icon strip, and a button on the CalTopo map's row ("3 new · 1 waiting"). It opens the list: added, changed, removed, with the name and when; click one to see it in the list and on the map. Below it, your edits waiting for CalTopo: Open on a conflict shows both versions, Send now tries again. Opening the list counts as looked at.
  • Sending the project's items to CalTopo. Items the CalTopo map doesn't have are marked not in CalTopo. Nothing is sent by itself: Send to CalTopo… in the menu of an item or a folder, the Send to CalTopo button beside the badge in the info panel, or ⇪ Send N to CalTopo above the lists (all of them). FLEX first lists what goes and which CalTopo folders it will create (folders are matched by name, so an existing “Pits” is used); after your OK the items are added one after another with a progress bar, and a summary says how many were added, how many wait because CalTopo couldn't be reached (they go by themselves) and which failed and why. Points become markers, lines and areas shapes, with name, description, colour and symbol. An item sent is remembered in the project, so it isn't sent twice, and its mark goes. The project keeps its copies unless you choose Remove the project copies… afterwards (asks again; undo in History). When more than 10 items wait (you can change the number in the list), or an edit has waited for CalTopo over a day, a quiet note appears in Surface; Not now hides it until FLEX is opened again.
  • Rows in the CalTopo map's folders say waiting (your edit hasn't reached CalTopo yet), conflict, changed (in CalTopo since you last looked) or failed; a closed folder shows how many inside have one.

LiDAR

  • LiDAR loads point clouds: public datasets (Show OpenTopo Datasets shows what's available where you are), or a link to an ept.json. Clouds in the laszip form of EPT work, and so do .copc.laz files. EPT in the plain binary form does not load (the laszip form, which Entwine makes, does).
  • Your own scans: convert them with Entwine into a folder, then 🗄 Link Entwine with that folder and the address FLEX should serve it on (e.g. http://localhost:8083). FLEX starts and stops that server for you.
  • USGS Ref Fix (next to the point clouds) lifts a cloud whose heights are measured from the geoid onto the globe; it is on by default and auto turns it on or off from each cloud's projection when the cloud loads (most clouds need it). Flipping the switch yourself keeps your choice until you tick auto again.
  • Ground and height (in the LiDAR panel) colours by height above ground and can hide everything but bare earth.
  • Point cloud look (in the LiDAR panel, closed at first) sets how every loaded cloud is drawn:
    • Colour by: composite (the default mix of intensity and class colour), RGB, intensity, elevation, classification or return number (needs a cloud that carries return numbers).
    • Point size and Sizing: fixed (the same on screen at any distance), attenuated (smaller further away) or adaptive (follows how dense the cloud is where you look). Shape: circle, square or paraboloid.
    • Intensity: the Low and High values set the range that runs from dark to bright; Gamma bends the middle tones (higher is darker).
    • Eye-dome lighting shades points by depth, so shapes read without colour; its strength and radius are set below the switch.
    • Show classes: a switch per class that only hides its points on the screen. Nothing is removed from the cloud, and the noise classes (7 and 18) stay in the data and in the height filter.
    Reset goes back to FLEX's usual look. The settings are remembered on this computer and apply to every cloud, including ones loaded later.
  • Splat mode [beta] (in the LiDAR panel; off at first) draws the ground of a cloud as soft discs lying on the slope instead of single points, so it reads as a surface, coloured from a map layer. Ground is class 2 plus every point within the Ground band (0.3 m to start) of the ground the height filter works out (it keeps that filled while Splat mode is on). Each ground point becomes a disc tilted to the local slope. Fill sets its size as a multiple of the point spacing (raise it to close gaps); Max screen size and Max real size stop discs growing wider than that many pixels close up, or that many metres on the ground far away (where the points are far apart and the discs would be huge). Opacity makes the ground layer see-through, smoothly, like a map layer. Edge shading sets the dark rims eye-dome lighting draws where discs meet (0 = none; eye-dome lighting must be on). Ground colour from lists the layers of 🗺 Layers (the satellite layer to start); FLEX keeps the tiles it fetched for the part of the cloud you are looking at and fills in new ones as you pan, without a pause; where a tile is missing the points' own colour shows. Points above the ground (trees, shrubs) and below the ground (noise, returns under the ground) each have their own setting: small dark green dots (above) or small red dots (below) to start, the cloud's usual colouring, coloured by height above ground, or hidden. It is a look only: nothing is changed in the cloud or saved in the project, and it works on streamed clouds as they load. Beta: ground far outside the picture area keeps its own colour, very sparse clouds leave gaps at close range (raise Fill or Max screen size), and below-ground points are hidden behind the ground unless it has gaps.
  • Analyze works out, for an area, how dense the vegetation is (how bad the bushwhack) and where returns reach below the local ground — often where entrances are. If a run fails, the panel shows the reason in its status line (Error: …), and a log.txt is written next to the output with the same reason.

Jobs

Anything that takes a while shows in a small strip along the bottom of the map, and only while it is running, waiting or failed: terrain and hillshade made from LiDAR, offline-map exports, Analyze runs, sync-file imports, and CalTopo edits waiting for the network. Each row has the job's state, a bar or its step (like “2/4 CSF cloth DEM”), the time it has taken and the buttons that apply: Cancel stops terrain, export and Analyze jobs on the server; Log shows everything the job has written; Retry runs a failed terrain, export, Analyze or sync-file job again with the same settings; Send now (CalTopo edits) tries to send them at once. Click the header (“Jobs: 2 running”) to fold the strip down to a pill; the map stays visible. A finished job shows Done ✓ for 30 seconds, then goes; a failed one stays until you dismiss it (×). The last ten jobs stay behind Recent jobs. The first time a job starts, FLEX asks whether it may send a browser notice when a job ends while this tab is in the background; say no and nothing is sent. Terrain, export and Analyze jobs keep running on the server if you reload the page, and the strip picks them up again.

Units (Settings → Units)

Distances, heights and depths are in metres and kilometres. Switch to Imperial for feet, miles and feet of climb; the choice is kept on this computer. It applies to the details panel and the route graph.

Offline maps (Settings → Offline maps)

As you browse, FLEX keeps the map tiles and point-cloud data it loads on this computer, so a place you have already looked at opens faster and still opens when the network is gone (open FLEX once while online so the app itself is kept too). The height filter also keeps its ground grid, so coming back to a place is instant. The oldest data goes first once the size limit (2 GB at first; change it there) is reached, and Clear cached map data empties it. Not kept: anything that needs a key or login (CalTopo's private maps, the CalTopo API) and Cesium ion's terrain and imagery. It only works at localhost or an https address. The app's own files are always fetched fresh, so an update shows up the next time you open FLEX.

Offline viewer and FLEX Field

Export bakes an area into a viewer that needs no network: draw a box or polygon (or load a KML), choose the terrain source (LiDAR for the finest, or the map's terrain for any size), imagery, and how caves are drawn. The result is a zip:

  • viewer.html opens in any browser on its own;
  • the same zip opens in the FLEX Field Android app (Import map, or Open with / Share from Files or Drive), where GPS and compass work underground.

In FLEX Field

  • Tap targets (the stations and leads you tap on the map) are sized in screen pixels, so they are the same size on any phone.
  • Names are thinned: where stations crowd together, the names that would overlap are hidden and the important ones stay. Zoom in to see the rest.
  • ⋯ → Route difficulty sets what counts as narrow (below 3 ft wide by default), stooping, crawling or steep, with − and + for each limit and a reset to the defaults. These limits set the difficulty colours and the route figures.
  • Big exports are tiled: an export over about 5 km is cut into tiles, each with its own satellite and hillshade picture, so the imagery stays sharp at any zoom. Nothing to set.

Shots from a scanned page

Notes written as a shot table (From, To, Length, Azimuth, Inclination, LRUD, notes; feet or metres, backsights too) go straight into a field survey on the phone, with no connection:

  1. In FLEX Field: 🔧 → 📐 Field survey (a survey, or the list) → 📷 Import shots from scan. Or on a document's page: ✎ Edit → ⋯ → Import shots from this page.
  2. Choose Photograph a page (the phone's camera app takes it; the photo is kept as a Shot table document), a page from Documents, or a photo or scan file. Flat, well lit, the whole table in the picture.
  3. The phone reads the page itself, offline, and shows the table under the page (beside it when the phone is on its side). Orange cells are worth a look (a letter read as a digit, a decimal comma, a word the reader was unsure of), red ones are wrong as they stand (an azimuth over 360). Tap a cell to see it on the page; tap the page to find its cell; pinch to zoom; ⟳ turns a sideways page.
  4. Each column has a menu saying what it holds (From, To, Length, Azimuth, Incl., Back az, Back incl., L, R, U, D, Notes, Ignore). Type in any cell to fix it; ＋ Row, ⊘ Skip, ⇅ Merge (one shot read as two rows) and 🗑 Delete act on the rows whose numbers you tap. Choose ft or m.
  5. Add … shots to a field survey, or a new one. They are worked out and drawn like typed shots, each remembers its page, and the page is tagged with the stations it covers (for example T6~T12), so a station's card lists it.

A half-checked table is kept for its page until its shots are added. In a browser (the offline viewer on a computer) the page is shown beside an empty table to type into: reading handwriting needs FLEX Field.

Exports need Python with PDAL, GDAL, NumPy, SciPy and Pillow. The simplest route is conda:

conda create -n entwine -c conda-forge python pdal python-pdal gdal numpy scipy pillow

Building FLEX Field needs Android Studio's SDK; in PowerShell:

cd android
.\gradlew.bat installRelease

Rebuild it after updating FLEX to get viewer changes onto the phone. Existing maps on the phone keep working.

Sync files

  1. Make one Project → Sync files → ⇧ Make: changes since last (or Everything for someone new). It is a zip: send it by any means.
  2. Import it on the other computer ( Project → ⇩ Import…, or ⇩ From a sync file… with no project open) or in FLEX Field.
  3. Review what came in: suggestions (from the phone, a helper, or the archive processor) wait in Review and change nothing until accepted.
A sync file carries survey data and cave positions. Send it only to people who should have them.

Performance

When FLEX feels slow, open Speed (bottom of the strip, above Settings; it opens in the dock panel at the bottom left, so you can keep it open while you work in another panel). It always measures the frame rate and, for every frame, how long each kind of work takes: point clouds, terrain & globe, map layers, features & lines, labels & points (the cost of many names and point markers), FLEX's own work (minimap, compass, measuring, incidence lines) and the GPU. The coloured bar is one frame, in milliseconds; beside it are counts (points on screen against the point budget, terrain tiles, features by source, map layers shown, Google 3D model, shading).

Run tests finds what is worth turning off. It switches one thing off at a time for about a second (names, each big folder, the CalTopo map, each data file, half the point budget, shading, the Google 3D model, terrain patches, the minimap, incidence lines, the height filter), measures how much faster the view gets, and puts it back exactly as it was. The view flickers while it runs, so it only runs when you press the button. The result is a bar per test and a list of suggestions, best first. Nothing changes until you press Apply; Undo puts the old setting back.

Under the frame rate the panel says in words whether the view is smooth, slow or jerky (several frames in 10 seconds that take over twice as long as usual, which looks like stuttering even when the average frame rate is fine), with the slowest frame and the "1% low" rate. A long frame is shown as it is (a frame of 1,000 ms is one frame a second at that moment), and seconds with stutter are marked in red above the little history graph. With hundreds of names on the map FLEX shows only the nearest readable ones (about 300, none overlapping, within a distance that shrinks as there are more) and works out the ground height under each point once, keeping it on this computer, instead of re-measuring every frame.

If the view stays under 20 frames a second for 10 seconds, or is jerky for that long, a small Running slowly — see why (or Running jerkily) note appears (once per session, not while a project is loading). It only opens the panel; it never runs tests by itself. The GPU time is an estimate (the frame time minus the measured work) unless your browser offers a GPU timer; the panel says which.

When something's wrong

  • Black screen with stars, no globe: FLEX tries to recover by itself after a few seconds. If it stays black, toggle any map layer off and on in Layers. If it happens again, open the browser's console (F12) and copy the line starting with [globe] — it says what was missing.
  • No terrain or imagery at all: check the Cesium ion token in Tokens.js.
  • A private CalTopo map won't load: check the key in Surface → CalTopo map: link and key (🔑).
  • "Survey file not on this computer yet": a project names a survey file this computer doesn't have; import the sync file that carries it.
  • Slow with a big project: hide point clouds you don't need, and lower the Point Budget in LiDAR.
  • Something else: restart the server (node server.js) and reload the page; your work is saved in user_files/.
