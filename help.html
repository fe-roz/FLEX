FLEX guide

FLEX shows everything about a piece of ground at once: the globe and terrain, map layers, LiDAR point clouds, surface points and tracks, and 3D cave surveys. Work is kept in projects (one per area), and any area can be baked into an offline viewer that runs on a phone underground.

Setting up

FLEX is a small program (a Node server) that you run on your own computer, opened in a web browser. Your data stays on your computer.

  1. Install Node.js Version 18 or newer, from nodejs.org (the LTS installer is fine).
  2. Get FLEX and its parts Download or clone FLEX from GitHub, open a terminal in its folder, and run: 
    npm install
  3. Add your map keys Copy Tokens.js.example to Tokens.js and paste in a Cesium ion access token (a free account at ion.cesium.com → Access Tokens). That token gives the 3D terrain and Bing imagery. A Google Maps key is optional, for Google's photorealistic 3D tiles. Tokens.js stays on your computer: it is never committed or shared.
  4. Start it 
    node server.js
    then open http://localhost:8081/index.html in Chrome or Edge. On Windows you can make a FLEX.bat that does both (it is ignored by git, since it holds your own paths).
  5. Optional: CalTopo, LiDAR, exports Each is set up when you first need it: a CalTopo key for private maps, a local Entwine server for your own point clouds, and a Python environment for offline viewers.
Updating: 🔄 Updates in the top bar shows when a newer version of FLEX is available and fetches it (FLEX must be a git checkout). Restart the server after an update.
Keep FLEX's folder private bits private. user_files/ (your projects, My data, keys), Tokens.js and FLEX.bat are never part of FLEX on GitHub. Survey data and cave locations are sensitive: share them with sync files, on purpose, with the people you choose.

Your first area

  1. Make a project 📁 Project → ＋ New project. Give it the area's name. Your name (asked once) is written on every change, so friends can see who did what.
  2. Bring in a cave 🕳 Caves → + Import PLT / Breakout / Walls. Then place it: select a station, Anchor a station to the globe at the entrance, and check the magnetic declination. More stations pinned as control points warp the survey to fit.
  3. Add the surface 📍 Surface: draw points, lines and areas, import KML / GPX / GeoJSON, or link a CalTopo map so the group's markers and tracks appear.
  4. Add layers 🗺 Layers for imagery and hillshade — and Your map layers for your own: a GeoTIFF or a tile link (see below). ☁ LiDAR for point clouds.
  5. Save 💾 Save puts the changes into the project (the count shows how many are waiting). See Saving.

Projects and My data

A project is everything about one piece of ground, kept in one folder: its caves and where they are placed, surface points and tracks, documents, leads and notes, the CalTopo map and point clouds it uses, and the history of every change. One project is open at a time. Friends get a project by sync file.

👤 My data is your own collection, outside any project: anything you load or draw with no project to put it in lands there, and stays across sessions. It is never synced. Built-in maps belong to neither.

Selecting in 3D

Each click on the same cave goes one level deeper; the details panel shows where you are.

🕳 Ridge Cave›Survey A›Segment 3›Station A12
  • A click inside the selection goes one level deeper. Segments are skipped where there are none or they are turned off.
  • A click elsewhere selects the same level there: with a survey selected, the next click selects another survey.
  • Clicking the selected station again goes back to the cave. Empty space or Esc clears it.
  • Right-click a cave for a Select menu with every level, to jump straight to one.
  • Double-click a cave's name in 🕳 Caves to fly there.

Friends with FLEX get a project the same way: a sync file, made in 📁 Project and imported on their computer. Each computer only adds to its own log, so nobody overwrites anybody; edits made in two places to the same thing are kept side by side for you to choose.

The project folder

Each project is a folder, by default in user_files/projects/<name>/; it can be anywhere, a shared drive folder included. Put scans, reports and maps in it however you like; 📄 Docs shows it as it is on disk. FLEX keeps its own information in a hidden .flex folder inside it.

Caves

  • Import: 🕳 Caves → + Import PLT / Breakout / Walls (Compass .plt, Breakout exports, Walls shapefile exports).
  • Place: select a station → Anchor a station to the globe. Add control points (more stations pinned to known spots) to rubber-sheet the survey into place. Check the magnetic declination; the wizard can look it up from the World Magnetic Model.
  • Style: each cave's ⋯ menu, or 🎨 All caves at the top of the panel for every cave at once: dots, names, colour, walls (blocky / smooth), opacity, area names.
  • Colour by survey, elevation, depth below ground, or difficulty.
  • Replace survey file keeps the placement when a cave's survey is updated, and warns about stations that changed.

Surface features

📍 Surface lists the project's things on the left (its CalTopo map, folders of points, lines and areas, data files) and 👤 My data on the right. ▸ opens a row in place: a folder shows its folders and features (click one to highlight it, double-click to fly there, ✏️ to edit); the CalTopo map and data files show their own folders, each with its box.

  • Surface shown / hidden (the switch at the top) hides or shows everything on the surface at once — project features, CalTopo, data files and your points — without changing what each one is set to. The 📍 icon is struck through while it's hidden.
  • 📍 Surface → ＋ Point / Line / Area to draw, or import KML / KMZ / GPX / GeoJSON. Points can carry lead details (status, needs, priority).
  • Folders work like CalTopo's; ⇩ downloads a folder as KML / GPX / GeoJSON to upload to CalTopo.
  • Cave entrances marked on points (flex: cave=…; station=…) are listed in 🕳 Caves → Cave entrances on the map, with Place the cave here.
  • Very long GPS tracks are drawn simplified (to about 2 m), so they don't slow the map; the full track is kept.

Your own map layers

🗺 Layers → Your map layers:

  • ＋ GeoTIFF… — a hillshade, an orthophoto or a georeferenced scan, in lon/lat (EPSG:4326), UTM (WGS84 or NAD83) or Web Mercator. A DEM (one band of heights) is turned into a hillshade. FLEX keeps one picture of it (at most 4096 pixels a side) with where it goes. Other projections: save the file as lon/lat or UTM first (e.g. QGIS → Export → Save As, or gdalwarp -t_srs EPSG:4326).
  • ＋ Tile link… — any map served as tiles, with {z}, {x} and {y} in the link. A key in the link travels with the layer, so don't add private keys to a shared project.

With a project open, a new layer goes into the project (📁) and travels with it; with none, into 👤 My data. The box and the slider (how see-through) are yours alone. They're drawn above the built-in layers.

CalTopo

Paste a CalTopo map link in 📍 Surface → CalTopo map: link and key. Public maps work as they are. Private maps need a key, kept only on this computer (never in a project, sync file or git):

  • Team account: Team Admin → Details → add a service account with READ. Enter its credential ID, secret, and the team ID.
  • Personal account: the credential from caltopo.com/api/v1/activate (unofficial; it may stop working if CalTopo changes it).

With an account or team ID, Pick a map… lists your maps. FLEX re-reads the map every so often, so the group's changes appear. To link a cave to its entrance marker, put a line like flex: cave=Ridge Cave; station=E1 in the marker's description.

LiDAR

  • ☁ LiDAR loads point clouds in EPT format: public datasets (Show OpenTopo Datasets shows what's available where you are), or a link to an ept.json.
  • Your own scans: convert them with Entwine into a folder, then 🗄 Link Entwine with that folder and the address FLEX should serve it on (e.g. http://localhost:8083). FLEX starts and stops that server for you.
  • Ground and height (in the LiDAR panel) colours by height above ground and can hide everything but bare earth.
  • 🌿 Analyze works out, for an area, how dense the vegetation is (how bad the bushwhack) and where returns reach below the local ground — often where entrances are.

Offline viewer and FLEX Field

📦 Export bakes an area into a viewer that needs no network: draw a box or polygon (or load a KML), choose the terrain source (LiDAR for the finest, or the map's terrain for any size), imagery, and how caves are drawn. The result is a zip:

  • viewer.html opens in any browser on its own;
  • the same zip opens in the FLEX Field Android app (Import map, or Open with / Share from Files or Drive), where GPS and compass work underground.

Exports need Python with PDAL, GDAL, NumPy, SciPy and Pillow. The simplest route is conda:

conda create -n entwine -c conda-forge python pdal python-pdal gdal numpy scipy pillow

Building FLEX Field needs Android Studio's SDK; in PowerShell:

cd android
.\gradlew.bat installRelease

Rebuild it after updating FLEX to get viewer changes onto the phone. Existing maps on the phone keep working.

Sync files

  1. Make one 📁 Project → Sync files → ⇧ Make: changes since last (or Everything for someone new). It is a zip: send it by any means.
  2. Import it on the other computer (📁 Project → ⇩ Import…, or ⇩ From a sync file… with no project open) or in FLEX Field.
  3. Review what came in: suggestions (from the phone, a helper, or the archive processor) wait in ✓ Review and change nothing until accepted.
A sync file carries survey data and cave positions. Send it only to people who should have them.

When something's wrong

  • Black screen with stars, no globe: FLEX tries to recover by itself after a few seconds. If it stays black, toggle any map layer off and on in 🗺 Layers. If it happens again, open the browser's console (F12) and copy the line starting with [globe] — it says what was missing.
  • No terrain or imagery at all: check the Cesium ion token in Tokens.js.
  • A private CalTopo map won't load: check the key in 📍 Surface → CalTopo map: link and key (🔑).
  • "Survey file not on this computer yet": a project names a survey file this computer doesn't have; import the sync file that carries it.
  • Slow with a big project: hide point clouds you don't need, and lower the Point Budget in ☁ LiDAR.
  • Something else: restart the server (node server.js) and reload the page; your work is saved in user_files/.
